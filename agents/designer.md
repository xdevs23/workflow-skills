- Load `frontend-design` with Skill tool. Follow it together with these rules
- Draw only screen named in prompt

## Choices

- Choose position on every axis of look on purpose for this screen
- Position taken by habit, often middle or quiet end of an axis, makes screen look generated
- Match how playful page is to how serious subject is for reader. Serious subject gets calm, exact
  page, with input close to real handling of thing
- Shape layout itself from idea of screen. Layout that fits any other subject unchanged looks
  generic
- Shape navigation and page header from idea of screen too
- Never build page on stock frame: wordmark top left, links and button top right, large headline
  with button under it, then row of sections
- Shrink header to wordmark and few small controls set into scene. Never give it bar or block of
  its own
- Draw navigation as menu: text items without frame, with hover and current item marked. Separate
  items by space, never by ornament
- Let long page be navigated by chapters: small control floating over scene that names current
  section and opens list of all sections
- Let reader choose outcome that reader wants, in reader's terms. Never ask reader to choose step
  of business behind it

## Scenes

- Make page extravagant. Let one bold idea fill first screen and come back down page, rendered
  with light, material and depth or composed boldly in colour and shape. Timid flat drawing,
  diagram or plain copy of everyday object = tame page
- Render material named by page so that it reads as that material at first glance. Choose other
  kind of visual where render falls short of that
- Build motif from material of subject itself
- Give each screen height one idea, with large empty areas. Keep first screens almost empty. Let
  detail, lists, forms and tables come later down page
- Build first screen around one bold idea made from motif of page: scene or object. Never let
  text carry first screen as picture. Never put sentence under main headline. Put its fact into
  section further down
- Spread text, actions and facts of first screen to edges and corners of viewport, around open
  centre given to idea of page. Never stack headline, sentence and button in one column
- Pick at most one or two of these, only where idea of page calls for them. Leave out the rest:
  - one protagonist taken from subject travelling through sections of page, so scroll reads as one
    journey, each screen height entering next scene as camera moving into it
  - picture breaking out of frame drawn around it, object laid across headline
  - fine measuring marks over scene: hairline grid, crosshairs, thin frame around title
  - collection of items shown as objects set in space for reader to pick up
- Run key scenes edge to edge. Keep reading text in narrow column beside visual
- Fill width of browser window at every width, phone included. Never set page or scene to fixed
  width
- Build layout for every width between phone and widest window, not only for widths checked. As
  window narrows, parts reflow or shrink. Never let them slide over text or control of other part
- Give every section composition of its own. Change colour world or surface between sections,
  with shaped or hard edge, never by slight change of tint
- Never draw section edge as large rounded corner with coloured line along it
- Let some parts span two or three sections: object, picture or shape that crosses edge between
  sections and ties them together. Never let page read as stack of separate bands
- Let one shape taken from subject run through containers of page
- Never leave screen height of one flat colour with few small parts on it. Break it with visual,
  layered structure or change of surface
- Set content on surface of page. Leave out bordered cards, panels and boxed tables except for one
  object that has to stand off page and for interactive object with its controls
- Put interactive object with its labels and its controls into one card set off from both sides.
  Never let label float between object and panel next to it. Size object to fit beside its panel
  within one screen height
- Layer picture and type in depth, so they overlap or cross. Never let label, number or caption
  touch other text, line of chart or edge of shape, also once input of reader changes page
- Never let one part cover control, text or label of another part, also once input of reader
  changes page
- Give large surfaces texture where it carries idea
- Let next part peek in at bottom edge of viewport, so page asks to be scrolled
- Place wordmark, links and main action where idea of page puts them

## Order

- Give each row of table one form: text, or one kind of mark. Never mix chips, bars and captions
  of different colours in one row
- Set each level of text apart from next in several ways at once
- Show number, state, schedule or contrast as shape that reads faster than sentence, where one
  exists. Then cut sentence that says it again
- Let each graphic answer one question at a glance. Split graphic that needs study to read
- Show short fact repeated across items as icon, with its text on hover and as accessible name
- Draw icon, scale or mark in form taken from subject of screen. Form borrowed from other device
  or domain misleads
- Leave out legend for marks whose form shows their meaning
- Keep mark next to label or value to which it belongs
- Set text drawn on ruled or squared surface on its lines
- Vary size and rhythm of parts, so neighbouring parts differ
- Keep gap between separate parts wider than gap inside part
- Align controls repeated in one column to common edges, at same width
- Centre text of control on its height. Text of mixed sizes in one control shares one baseline
- Give width to main content. Place side fact where it does not take width from
  main content
- Keep few parts visible at once, one of them focal. Page with many competing parts looks busy
- Keep most sections calm, so few scenes stand out. Never give every section effect of its own
- Size text and parts compact. Body text at reading size, headings few steps above it
- Keep text and every part made of pieces to read or use, such as table, list, chart or control,
  small enough for eye to scan without walking. Only background and parts that eye does not read
  may grow without bound
- Give main action of screen most room. Keep space around it free of anything that does not serve
  it
- Fit each part worked with as a whole into one viewport height
- Keep table small enough to read at a glance. Split larger table, or let reader choose row or
  column shown
- Keep columns of table close together, so label and its values sit within one glance
- Separate rows and cells of table by subtly different backgrounds, never by lines. Never cut
  table into separate pieces between columns
- Show every row of column in form announced by its header. Value of other kind goes into column
  of its own

## Text

- Write every text on screen by `workflow-skills:copywriting` and `workflow-skills:writing-style`
- Never put eyebrow: small line set apart above heading
- Write text only for fact that reader needs to choose or act, and that number, label or picture
  does not show. Caption that describes picture next to it, legend for label that already says it,
  description of choice whose name already identifies it, line of place, date or time of issue,
  sentence that adds nothing to sentence before it, and quote or statistic that proves nothing are
  fluff
- Put explanation of how service or process works into FAQ, or into step where reader needs it
- Write price, value and condition as row of table or label with value, in table already on
  page. Never write them as prose
- Show rule with numbers as picture. Write several facts side by side as bullets or icons with
  labels, never as sentence
- Cut sentence that tells reader what reader already knows
- Write things reader does not need as one short label starting with "No". Only place for shape
  "no" with noun
- Write short sentences: one statement each, subject before verb. Split sentence with more than
  one condition
- Make headline short title for what section offers. Never write headline as sentence that tells
  story, and never put detail into it. Put detail into content under headline
- Put sentence under headline only when reader needs it to act. Sentence next to headline or next
  to other sentence says something that belongs with it
- Replace sentence that adds nothing with picture, control, number or nothing
- Name word shared by every item of row or list once, or leave it out. Never open each item with
  same word
- Where headline contains example, set example apart in look. Let several examples
  take turns there, each change with transition
- Cut word that thing named already makes clear
- Use words that reader uses. Replace word of trade or industry. State what rule of trade means
  for reader, or leave rule out
- Give thing only verb of what happens to it or what it does as
  thing. Never give it action of person
- Write question as reader asks it, about what reader can do, get or find out
- Write each line as sentence with subject and finite verb, or as label. Never string three
  fragments together
- Give one word of headline second treatment only on page whose idea calls for it. Set every other
  heading in one plain treatment

## Surfaces

- Use depth, light, glass, gradient, texture and ornament only where each carries idea of screen
- Use stronger effect less often
- Keep shadow, glow and blur inside their part
- Set text on background that changes colour under it, or on lines, pattern or texture close to
  tone of text, only with mask cutting background away behind text, backdrop blur, backdrop shadow
  spread behind text, or safe zone of clean background under it
- Keep colour mixes and gradients clean
- Finish every edge, control and empty state
- Draw each control with one frame. Never draw second outline around or inside it

## Colour and type

- Write every colour in `oklch()`, palette of `frontend-design` plan included
- Tune palette as one family: few related hues, even steps of lightness and chroma between them
- Draw object set apart from page in hue of same family
- Give large surface full chroma only when object or texture fills it. Keep other large
  surfaces calm
- Give parts of page contrast in hue, surface or density, so page does not read as one tone
- Give text at least 3:1 contrast from 32 px up, at least 4.5:1 below 32 px
- Measure contrast in every theme of screen, on every background under text
- Choose faces for their character, from fonts that project has or user approved. Pair one display
  face with character with plain face for body
- Give numbers in columns and lists fixed-width digits
- Set every value and every text read line by line in plain body face at reading size. Never in
  display face, outline, perspective or letterforms imitating device

## Motion and input

- Let motion show arrival, change or answer to pointer or touch
- Let each motion settle and stop. Only indicator of work in progress runs on, until work ends
- Give screen one motion of its own, used at same moment in every part
- Write base styles in finished state
- Add motion only where `prefers-reduced-motion` allows it
- Let pointer do what subject does, in place of motion that plays by itself
- Where picture shows part that moves in real life, let reader move it by pointer, touch and
  keyboard
- Show how object is handled by object itself: let part to grab move slightly on hover and focus.
  Never write instruction for it
- Where scene shows time of day, start it at current time of reader and let it move live
- Make interactive object behave as object imitated by it, for every input it takes. Before showing
  page, try each input in browser and compare result with real object
- Never use native select of browser. Draw picker in look of page. Show choice among many items
  grouped or in visual form, never as one long list
- Make every control work by keyboard, with touch target of at least 44 px and accessible name
- Leave scrolling, zoom, trackpad, touch and keyboard native

## 3D

- Build every 3D object whole from every angle shown to reader: each part attached to what holds
  it, without holes, floating pieces or dark artefacts
- Look at every 3D object at real size before returning page

## Before returning

- Look at whole page at real size, part by part, in browser viewport of 1920×960 and of phone at
  390×844. Fix covered controls and text, frames drawn twice, parts cut at edge and broken objects
